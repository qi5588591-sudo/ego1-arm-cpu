# EGO1 ARM A32 单周期 CPU

本阶段是 ARM 基础单周期实现，已实现 21 条基础指令；五级流水线和 MUL/SDIV/UDIV 将在下一阶段加入。当前不宣称已完成第四题。

## 打开与下载

只打开：`D:/Code/Vivado/ego1_arm_single_cycle/ego1_arm_single_cycle.xpr`。

设计顶层：`ego1_arm_top`。器件：`xc7a35tcsg324-1`。默认仿真顶层：`tb_arm_cpu`。

构建结果见 `reports/build_result.txt`。构建成功后，在 Hardware Manager 中连接 `xc7a35t_0`，Program Device 选择：

`D:/Code/Vivado/ego1_arm_single_cycle/download/ego1_arm_single_cycle.bit`

原先的 LoongArch 工程保持独立，不要把其 `.bit` 当成本 ARM 工程的结果。

| 指示灯 | 引脚 | ARM 程序正常运行后的预期现象 |
|---|---|---|
| D16 | K3 | 每 0.5 秒翻转，表示 100MHz 板载时钟在运行 |
| D15 | M1 | 常亮，表示测试程序完成并通过结果检查 |
| D14 | L1 | 熄灭；亮起表示 CPU 或程序结果错误 |

按住 S0/R11，D15、D14 熄灭，K3 继续闪烁；松开后程序重新运行，D15 应重新亮起。用户于 2026-10-28 确认三盏灯及复位重跑现象符合预期。

如果重新连接时出现 No devices detected，可以按之前有效的方式降低 JTAG 扫描频率至 125000Hz。下载器的扫描频率与 CPU 的 1MHz 时钟不同。

## 已支持的真实指令与形式

| 类别 | 指令 | 数量 |
|---|---|---:|
| 算术 | ADD、SUB、RSB、ADC、SBC | 5 |
| 逻辑 | AND、ORR、EOR、BIC | 4 |
| 移动 | MOV、MVN | 2 |
| 比较 | CMP、CMN、TST | 3 |
| 访存 | LDR、STR、LDRB、STRB | 4 |
| 分支 | B、BL、BX | 3 |
| 合计 | | 21 |

采用标准 A32 编码，包含以下明确子集：

- 标准条件码与 AL；条件不满足时没有寄存器、标志或内存写入。cond=1111 扩展编码空间不支持。
- 运算的 S 形式更新标志；CMP/CMN 更新 NZCV；逻辑与 TST 按移位输出更新 C，保留 V。
- Operand2 支持旋转立即数和立即数控制的寄存器移位：LSL、LSR、ASR、ROR、RRX；包括 LSR/ASR #32。
- 不支持寄存器控制移位、MOVW/MOVT、TEQ/RSC、半字传送、基址回写和后索引。
- 访存采用立即数正/负偏移，P=1、W=0、I=0。字访问必须按 4 字节对齐；字节加载零扩展，字节存储只更新对应一个字节。
- R0 是普通寄存器；R0～R14 可读写，读 R15 返回当前指令 PC+8。普通运算和加载写 R15 暂不支持。
- B/BL 的目标由当前指令 PC+8 加有符号偏移得到，BL 将 PC+4 写入 R14。
- BX 支持回到 A32 状态、4 字节对齐的目标，不实现 Thumb 状态切换。

这是课设所需的 ARM 指令子集，不是完整 ARMv7 系统实现。`fault` 是实验诊断：非法/未支持编码、非法取指、非法数据地址或未支持跳转会停止 CPU，禁止出错指令的写操作，复位可以清除。它不实现 ARM 特权模式与异常入口。

## 存储器与演示程序

CPU 每个 1MHz 时钟周期完成一条有效指令。ROM 异步读；RAM 异步读、同步写，采用小端字节顺序。

| 地址 | 用途 |
|---|---|
| 0x00000000 起 | 演示程序 ROM，166 个 32 位机器码 |
| 0x00001000～0x000010FF | 256 字节数据 RAM |
| 0x00001000 | 7+5 的结果，期望 12 |
| 0x00001004 | 1+2+3+4+5 的结果，期望 15 |
| 0x00001008 | 完成标记，成功为 1，程序主动发现失败为 0xEE |

RAM 在 FPGA 配置时初始化为零，CPU 复位时保留。板级通过灯要求一次新的完成写入，避免把上次运行留下的标记误判为本次成功。

`programs/demo.s` 是完整的 ARM 汇编演示，包括 R0 读写、算术/逻辑、NZCV、条件执行、移位特殊值、字节写入、正负偏移、PC+8、BL/BX 调用返回和向后分支循环。

## 验证方法

`scripts/build_programs.py` 调用本机 LLVM Clang 14 的真实 ARM 汇编器生成 ELF；提取 .text，并处理本地分支重定位。每条源指令必须恰好对应一个 32 位机器码，不使用隐藏文字池或多字伪指令。

期望行为由按汇编语义执行的 Python 参考模型产生，模型不复用 Verilog 译码器。Verilog 仿真逐条比对 PC、机器码、下一 PC、条件结果、寄存器写回、访存地址/数据/大小及 NZCV。

- 演示：166 个机器码，181 条动态指令，21 条基础指令均被实际执行。
- 固定种子的随机测试：600 条随机指令，连同初始化和终止循环共 661 条动态指令。
- 条件逻辑：16 种编码 × 16 种 NZCV，共 256 种组合。
- 10 类错误：非法编码、无效取指、数据越界、字地址不对齐、Thumb 目标、cond=1111、写 PC、后索引、寄存器控制移位和非法字节存储。
- CPU 合计 12969 项检查通过，见 `reports/cpu_simulation.log`。
- 板级 26 项检查通过，见 `reports/board_simulation.log`；包含真实 /100 分频、复位、重跑、心跳与错误灯路径。

上述是仿真验证；时序和规则检查结果见构建报告，真实上板现象须另行确认。

## 最终构建结果（2026-10-28）

已由本机 Vivado 2025.2 完成综合、布局布线和压缩 bitstream 生成。建立时间裕量 6.340ns，保持时间裕量 0.122ns，所有指定时序约束满足，内部未约束端点为 0；DRC 0 个问题，CDC 报告中的两个连接均为安全/信息级。

下载文件为 456298 字节，与 Vivado 实现目录中的原始 bitstream 哈希一致。USR_ACCESS 为 `41524D31`（ARM1），用于必要时核对实际加载的版本。物理上板灯光和复位重跑已由用户确认正常。本工程保留作为已验证的单周期基线。

## 建议的阅读顺序

1. `programs/demo.s`：先理解 CPU 要执行什么程序。
2. `rtl/arm_regfile.v`：R0 正常读写，R15 返回 PC+8。
3. `rtl/arm_condition.v`：条件码与 NZCV。
4. `rtl/arm_operand2.v` 和 `rtl/arm_alu.v`：移位、运算及标志更新。
5. `rtl/arm_single_cycle_cpu.v`：译码、PC、回写、条件门控和出错停止。
6. `rtl/arm_data_ram.v`、`rtl/arm_soc.v`：字节写使能与整体连接。
7. `rtl/ego1_arm_top.v`：已验证的 EGO1 时钟复位与指示灯方案。

在 Vivado 中 Run Behavioral Simulation 默认运行 CPU 全部测试；把 `tb_ego1_arm_top` 设为仿真顶层，可以观察板级运行过程。
